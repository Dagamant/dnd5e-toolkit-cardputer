# Development notes

Working notes for picking this project up again. The README covers building, controls,
the SD card layout and the serial console; this covers how the pieces fit and how to test.

## Layout

| Path | What |
|---|---|
| `src/main.cpp` | Start-up, app registry, launcher |
| `src/apps/*_app.cpp` | One file per app (`makeXxxApp()`), registered in `main.cpp` |
| `src/core/` | Shared UI (`ui.*`), text view with tables (`textview.*`), input, dice, sfx, prompts, web server (`web.*`) |
| `src/core/resources.cpp` | Class/feat/species counters and the actions that spend them (tables `POOLS` and `USES`) |
| `src/board/` | Device-specific code (start-up, keyboard, SD pins). The Tab5 port goes here: [TAB5_PORT.md](TAB5_PORT.md) |
| `web/index.html` | The whole web interface (one file, no build step) |
| `src/core/web_page.h` | Generated from `web/index.html` by `tools/web_embed.py` on every build (git-ignored) |
| `sdcard/gmtools/` | Card contents; `srd/` is generated by the extractor |
| `tools/` | Python and Node helpers, below |

## Tools

All Python tools run with `tools/.venv/bin/python` (`pip install pymupdf pyserial`).

| Tool | Use |
|---|---|
| `srd_extract.py PDF OUTDIR` | Builds `sdcard/gmtools/srd` from `SRD_CC_v5.2.1.pdf` (not in git; download from D&D Beyond) |
| `srd_tables.py` | Used by the extractor: rebuilds tables from text positions in the PDF |
| `srd_compare.py DIR DB [-v]` | Cross-checks our data against the 5e-bits/5e-database 2024 JSON (`src/2024/en`, MIT). Most differences are mistakes on their side (gear costs, garbled item text); use it to spot extractor bugs, don't copy from it |
| `srd_audit.py DIR [-a]` | Lists every table in the data and flags odd-looking ones (most flags are false positives: stat-block lines, section rows) |
| `sdsync.py LOCAL SDDIR` | Copies files to the card over USB. Always send a `.txt` together with its `.idx` |
| `dev.py "key down\|type x\|shot:name"` | Drives the device over serial; screenshots land in the current directory |
| `web_embed.py` | PlatformIO pre-build script (gzips the web page into firmware) |
| `web_mock.py sdcard web/index.html` | Fake device API on http://127.0.0.1:8766 serving the repo's card data, any PIN. Edit the page and reload, no flashing |
| `web_shot.mjs WxH steps.json` | Headless Chromium screenshots (`node --experimental-websocket`). Steps: `{go}` `{wait}` `{eval}` `{shot}` `{type}` `{key}` |

A `web_shot.mjs` steps file that logs in and captures the live table:

```json
[{"go": "http://127.0.0.1:8766/#table"}, {"wait": 800},
 {"eval": "document.querySelector('#pin').value='1'; document.querySelector('#loginForm').requestSubmit()"},
 {"wait": 2000}, {"shot": "table"}]
```
Web routes: `#table`, `#campaign`, `#notes`, `#ref/<file>/<offset>` (offset = first column of the `.idx`), `#files`, `#edit/...`, `#device`.

## SRD data pipeline

1. `srd_extract.py` reads the PDF with PyMuPDF, page ranges per section.
2. `runs()` turns pages into text runs in reading order; `srd_tables.py` finds table blocks
   (GillSans 8.5-9.9 pt), groups them (left/right/full-width), builds columns from where cells line up,
   joins wrapped headings and cells, and replaces them with one `tbl` run.
3. Tables are stored inside record text as lines of `cell | cell | cell` (first line = heading).
   Headless two-column tables are written as `Label: value` lines.
4. Each `.txt` is records separated by blank lines; the `.idx` is tab-separated with the byte offset first.

After changing the extractor: re-extract into a temp dir, diff against `sdcard/gmtools/srd`
(record counts and `.idx` columns should match unless intended), run `srd_audit.py`, then copy over and `sdsync.py`.

Hand fixes still in the extractor: Control Weather and Teleport tables, charge tables (`fix_charge_tables`).

Other layout fixes in the extractor:
- A heading bigger than an entry name ("Mounts and Vehicles", "Traps") ends the entry, so the next
  section doesn't read into the last entry. Stat blocks inside an entry (Figurine of Wondrous Power) are kept.
- A table named in another species' text ("the Fiendish Legacies table") is moved there (`move_species_tables`).
- Run-in headings ("Sunlight.", "1/Day Each:") start a new line; lines broken mid-sentence or mid-word
  by a block break are joined back up.
- The Adventuring Gear price list is dropped from Ammunition: its rows are the gear items.
- Option lists the PDF prints after level 20 (Metamagic, Eldritch Invocations) and the Wizard spellbook sidebar
  are moved onto the feature that uses them (`move_feature_sections`).
- A monster action name split into a bold-italic name plus a separate bold "." still starts its own action (metallic dragon breath).

## How tables are drawn

- Device (`TextView::addTable`): aligned grid if it fits; otherwise the widest column wraps (if it keeps 10+ chars);
  otherwise one block per row (`heading: value`). A short line without a full stop just above a table is its caption.
  Rows with only the first cell are section rows.
- Web (`tableEl` / `richText` in `index.html`): same `" | "` detection; wide tables scroll inside their card on phones.

## Testing on the device

- Flash: `~/.platformio/penv/bin/pio run -e cardputer-adv -t upload`, wait 3-4 s.
- Run `dev.py` from a scratch directory (it saves screenshots into the current directory).
- The screen dims after 90 s idle and swallows the first key: start command strings with `key down`.
- Launcher letter keys jump to the *next* app with that letter (from Monsters, `s` goes to Spells; from Spells, `s` goes to Settings).
  Enter on the first Settings row toggles Sound - easy to hit by accident.
- In list apps, `key back` first clears the search, a second one leaves the app.
- Don't use `pkill -f <name>` from a shell command that contains that name: it kills the shell itself.

## Web access

- The Web app (System group) starts the server; it keeps running after leaving the app.
- Hotspot name `DnD-Toolkit-XXXX` (from the MAC), password generated once and kept in NVS (`wap`), shown on the Web screen.
- Optionally joins a saved home network (W in the Web app), reachable as `http://dnd.local`.
- New 4-digit PIN on every start; 5 wrong tries locks it out.
- Joining the home network is tested on the Tab5.
- The page is `web/index.html`. `tools/web_embed.py` gzips it into `web_page.h` at build time.
- Routes besides the file API:
  - `/api/status` lists the apps that have a web side under `"apps"`.
  - `/api/app?app=<name>&op=<op>` (GET or POST) calls `App::web()` on that app. Each app answers from its own in-memory state, so the device and the page stay in sync. Changes carry an index plus a name (`i`, `who` or `name`); a stale one gets 409.
  - `/api/roll?title=` rolls `label|expr` lines (the POST body) on the device. The rolls go to the session log and the live roll feed.
- Apps with a web side: Dice, Initiative, Characters, Encounters, 5-Room Dungeon, Dungeon23, Hex Map, Random Tables, Magic Shop, Travel, Settings. To add one, override `web()`, answer `hello` with 200, and add the page to `NAV` and `views` in `index.html`.
- D&D Beyond import: Characters web op `import` (`link`) calls `ddb::import` (`src/core/ddb_import.cpp`, Tab5 only, uses ArduinoJson). Needs internet through the home WiFi.
- Testing: `node --experimental-websocket tools/web_shot.mjs 1280x900 steps.json` drives headless Chromium against the device. Run it from the scratchpad, because it writes its PNGs into the current directory. To log in with curl, send the PIN with `Content-Type: text/plain`.
